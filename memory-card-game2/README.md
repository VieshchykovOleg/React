# Memory Card Game

Цей проєкт є реалізацією гри на основі карток, де гравці повинні знаходити пари карток, перевертаючи їх. Виграє той, хто зможе знайти всі пари карток.

## Опис

В цьому проєкті я реалізував гру за допомогою **React**. Проєкт охоплює кілька ключових практик та патернів, таких як:

- Розбиття компонентів на менші та функціональні.
- Використання PropTypes для перевірки типів пропсів.
- Рефакторинг стилів за допомогою CSS-модулів.
- Використання Context API для управління глобальним станом.
- Перенесення логіки в кастомні хуки.

## Структура проєкту

### 1. Розділення компонентів на менші та функціональні

Я створив новий компонент `CardContent`, який відповідає за відображення контенту картки. Це підвищує читабельність та полегшує повторне використання компонентів.

**Як це реалізовано:**

- Створено новий компонент `CardContent`, який відображає значення картки або замінює його на знак питання залежно від стану.
- Компонент `Card` тепер використовує цей компонент для відображення контенту.

### 2. Використання PropTypes для перевірки пропсів

Додав бібліотеку **PropTypes** для перевірки типів пропсів у компонентах. Це допомагає уникнути помилок та забезпечує правильний тип даних.

**Як це реалізовано:**

- Встановлено бібліотеку `prop-types` за допомогою `npm install prop-types`.
- У компоненті `Card` додано перевірку типів для кожного з пропсів: `card`, `onCardClick`, `isFlipped`, `isMatched`.

### 3. Рефакторинг стилів: CSS-модулі

Я замінив звичайні CSS-файли на **CSS-модулі** для ізоляції стилів. Це дозволяє уникнути конфліктів стилів і забезпечує кращу підтримку стилів у великому проєкті.

**Як це реалізовано:**

- Замінив файл `Card.css` на `Card.module.css`, що дозволяє ізолювати стилі для компонента `Card`.
- Використано імпорти CSS з модулів, щоб застосувати стилі до елементів.

### 4. Контекст для управління станом

Я використовую **Context API** для спільного доступу до стану гри, що зменшує кількість пропсів, які передаються між компонентами.

**Як це реалізовано:**

- Створено контекст `GameContext`, що надає доступ до всіх станів гри (картки, перевернуті картки, стан гри).
- Компонент `GameBoard` використовує цей контекст для доступу до глобальних даних гри.

### 5. Хуки для логіки

Я виніс логіку перевірки пар карток та перемоги в кастомні хуки. Це дозволяє зберігати компоненти чистими та легко тестованими.

**Як це реалізовано:**

- Створено кастомний хук `useMatchCheck`, що відповідає за перевірку відповідності карток та стан перемоги.
- Використано хук у компоненті `GameBoard`, що дозволяє обробляти логіку в окремому місці, замість того щоб тримати її в самому компоненті.

## Висновки

Цей проєкт демонструє кілька важливих принципів, таких як компонування, перевірка типів, управління станом та тестування в React. Це дозволяє створювати більш підтримувані, зрозумілі та ефективні додатки.
